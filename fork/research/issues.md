# Decypharr open-issue triage

**As of 2026-09-26. Recommendation:** Keep Decypharr as the torrents/magnets/DMM side of the split, but do not fork from `main` without first auditing the active `beta` delta. Prioritize destructive-state and disk-exhaustion defects, then provider/API reliability and repair/index consistency. The strongest user-visible clusters are TorBox reliability (13 related issues, 8 reactions), repair/symlink/index consistency (12, 5 reactions), and resource/performance pressure (8, 6 reactions). The most-reacted single issue is TorBox CDN URL caching/rate limits, #300 (6 reactions). [Repository metadata](https://api.github.com/repos/sirrobot01/decypharr) reports default branch `main`; [v2.5](https://github.com/sirrobot01/decypharr/releases/tag/v2.5) is the latest stable release checked (published 2026-08-11), while [v2.0](https://github.com/sirrobot01/decypharr/releases/tag/v2.0) was published 2026-04-09. The [beta branch](https://github.com/sirrobot01/decypharr/tree/beta) had a 2026-09-16 head and was 167 commits ahead of `main` (0 behind) in the [compare API](https://api.github.com/repos/sirrobot01/decypharr/compare/main...beta): it is active, not a dead branch.

## Recommended cleanup order for a fork

1. **Choose a base deliberately:** compare the active `beta` branch to `main` first (167 commits ahead at snapshot); select a stable cut and retest old v1-era tickets instead of assuming they are fixed. The latest stable release observed is v2.5 (2026-08-11), while beta's head is 2026-09-16.
2. **P0: prevent data/config loss and host outages:** #343 partial `/api/config` wipe, #398 DFS cache exhausting filesystem, #400 queued TorBox downloads deleted as failures, and #298 downloads deleted before *arr import. Also reproduce #146 bad-download deletion and #407 shutdown leaving completed entries stuck. These have the clearest destructive or recovery cost.
3. **Audit already-written fixes before reimplementing:** candidate fixes #33/#34/#35/#36/#50/#51/#69 are merged to **Trifocals3537's external beta fork**, not `sirrobot01/decypharr`; #12 and #19 are also external-fork refs. They respectively target cache quota, account recovery, rejection cooldown, AllDebrid transient retry, raw infohashes, NZB rejection handling, and TorBox queued deletion. Review/backport as source candidates, not as upstream releases. Upstream candidates include #294, #305, #325, #424, and #426; #230 is merged to upstream beta but is only related/partial for #193.
4. **Stabilize provider and *arr contracts:** prioritize the TorBox cluster and typed outcomes/retry behavior (#300/#302/#308/#379/#400/#415/#417/#420), plus RD auth/account recovery (#375/#397/#409), AllDebrid retry (#335), and Premiumize link/index issues (#373/#423/#425). Ensure timeout/error responses tell *arr when to reject a release versus retry a provider operation.
5. **Make sync/repair/WebDAV state coherent:** reconcile provider entries, file/name indexes, symlinks, and repair results across #113/#122/#193/#244/#364/#413/#423/#428. Include DMM-created or externally cached items as a first-class sync acceptance case (#287), consistent with the brief's division of labor.
6. **Fix operator surface and deployment next:** #412 `URL_BASE`, #185 onboarding/configuration, #422 healthcheck when WebDAV is disabled, #371 image tag, plus stale support questions. Then prioritize feature backlog by actual use: provider priority #285, relative symlinks #317, Unknown Usenet repair #414, and hybrid library #405 before lower-signal additions such as Offcloud/PikPak and UI convenience requests.

No open issue is classified as **likely fixed in a released upstream version**: issue state and the retrieved PR references do not prove a fix shipped. Treat older v1 reports as stale/retest where marked, rather than silently closing them. In the table, `stale / needs-info` is triage guidance, not an upstream status change.

## Method and interpretation

Fetched on 2026-09-26 from the public GitHub repository. GraphQL returned all 71 open `Issue` nodes (`hasNextPage: false`) with title, full body, labels, created/updated timestamps, author, comment total, reaction-group counts, `closedByPullRequestsReferences`, and timeline `CROSS_REFERENCED_EVENT`s. The issue bodies are linked below rather than copied wholesale. **All 71 `closedByPullRequestsReferences` connections were empty**; PR associations shown are timeline cross-references, not evidence that a PR closed an issue. Linked PR metadata was checked for owner, state, merge date, and target branch. External-fork merges are explicitly marked. The repository metadata endpoint reports `open_issues_count: 134` (issues plus PRs); the GraphQL issue connection is the issue-only count.

`Version` gives the Decypharr version stated in the issue when identifiable. `v1-era*`/`v2-era*` means the body did not give a Decypharr version: it is only an inference from whether the issue was opened before/after v2.0 on 2026-04-09. Application versions such as Radarr/Whisparr were not mistaken for Decypharr versions. 35 bodies gave an explicit Decypharr version; the other 36 are date-era fallbacks. Labels are the actual GitHub labels (most issues have none). Reactions show the total and nonzero emoji breakdown. “Open without PR” means no relevant fix candidate was found; raw but unrelated cross-references remain visible in the PR column.
